VPS Installation and Update Instructions

Technician guide for the Maricho Media production server

Server64.247.178.45
Domainmshauri.marichomedia.com
Repositorygithub.com/seanndlovu/Mshauri-AI-Advisor
For an existing installation: go directly to “Routine Git update” on page 4. The repository contains the update script at deploy/3-update.sh.
Security: never commit deploy/.env.production, database passwords, Clerk keys, session secrets, or the configured Owner email to Git.

1. Point the domain to the VPS

Create or update this DNS record for marichomedia.com:

Type: A
Name: mshauri
Value: 64.247.178.45
TTL: 300 or Auto

Confirm it resolves correctly:

nslookup mshauri.marichomedia.com

2. Connect and download Mshauri

ssh root@64.247.178.45
mkdir -p /var/www
cd /var/www
git clone https://github.com/seanndlovu/Mshauri-AI-Advisor.git mshauri
cd /var/www/mshauri

If the repository already exists, do not clone it again:

cd /var/www/mshauri
git pull --ff-only origin main

3. Install server software

Run this once on a new Ubuntu VPS:

cd /var/www/mshauri
sudo bash deploy/1-install-vps.sh

This installs Node.js, pnpm, PM2, PostgreSQL, Nginx and Certbot.

4. Configure the production environment

cd /var/www/mshauri
cp deploy/.env.example deploy/.env.production
nano deploy/.env.production

Complete the values described in the file. Authentication requires the production Clerk credentials and these settings:

SettingPurpose
CLERK_SECRET_KEYServer-side Clerk authentication key.
VITE_CLERK_PUBLISHABLE_KEYPublic Clerk key used by the web application.
SESSION_SECRETLong random value used to secure server sessions.
OWNER_BOOTSTRAP_EMAILVerified email permitted to claim the first Owner role. Configure the approved first Owner email.
APP_ORIGINhttps://mshauri.marichomedia.com

Generate a session secret if needed:

openssl rand -hex 32
Use Clerk production keys on the VPS. Add mshauri.marichomedia.com to the production Clerk instance and configure the permitted redirect/origin settings there.

5. Build and launch the first installation

cd /var/www/mshauri
bash deploy/2-setup-app.sh

The setup script installs packages, configures PostgreSQL, builds the API and website, applies the database schema, configures Nginx and starts the API with PM2.

6. Enable HTTPS

Only continue after DNS resolves to the VPS:

sudo certbot --nginx -d mshauri.marichomedia.com
sudo nginx -t
sudo systemctl reload nginx

7. Verify the first installation

pm2 status
pm2 logs mshauri-api --lines 50
sudo nginx -t
curl -I https://mshauri.marichomedia.com

Open https://mshauri.marichomedia.com in a browser and test sign-in.

8. Activate Owner and staff access

  1. Sign in using the verified Clerk or Google account matching OWNER_BOOTSTRAP_EMAIL.
  2. Open https://mshauri.marichomedia.com/admin/staff.
  3. Claim the first Owner role.
  4. Additional staff must register or sign in once with their own verified email.
  5. The Owner can then assign Owner, Market Price Editor, Ad Manager, or No Staff Access.
The final remaining Owner cannot be removed or downgraded. Staff continue to use their own personal login details; assigning a role does not create or reveal a password.

9. Staff-access audit history

The current release permanently records staff role changes in PostgreSQL. The update script applies the required database schema automatically. Owners can review the history from the Staff Access area.

10. Routine Git update

After new code has been pushed to GitHub:

ssh root@64.247.178.45
cd /var/www/mshauri
bash deploy/3-update.sh

The script performs the following work:

  • Runs git pull --ff-only.
  • Reconciles PostgreSQL access and installs dependencies.
  • Builds the API and frontend.
  • Applies database schema changes.
  • Restarts mshauri-api with PM2.

Verify the update:

pm2 status
pm2 logs mshauri-api --lines 50
curl -I https://mshauri.marichomedia.com
If git pull --ff-only fails: do not run a forced reset until any local VPS changes have been reviewed and backed up. Check git status and preserve deploy/.env.production and uploaded advert files.

12. Common problems

ProblemAction
deploy/3-update.sh not foundEnter the cloned repository directory first, normally /var/www/mshauri.
API is offlineRun pm2 logs mshauri-api --lines 100 and check environment/database errors.
Database schema error after updateRun bash deploy/3-update.sh again after fixing the reported database configuration.
Clerk login failsCheck production Clerk keys, domain configuration, HTTPS, and application origin.
First Owner cannot claim accessConfirm the signed-in Clerk identity is verified and exactly matches OWNER_BOOTSTRAP_EMAIL.
Port 80 already in useCheck sudo lsof -i :80; disable Apache if it conflicts with Nginx.
