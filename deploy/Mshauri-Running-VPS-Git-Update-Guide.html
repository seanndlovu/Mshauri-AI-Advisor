Updating an Already-Running VPS

Final technician instructions for GitHub updates and the local-change error

VPS64.247.178.45
Domainmshauri.marichomedia.com
Repositorygithub.com/seanndlovu/Mshauri-AI-Advisor
This guide is for an existing installation. Do not clone Mshauri again and do not run the first-time installer. The routine update script is already inside the repository at deploy/3-update.sh.

1. What caused the error?

The VPS ran git pull --ff-only origin main. Git fetched newer commits, then stopped because the VPS had a local edit to:

pnpm-workspace.yaml

The newer GitHub commit also changes that file. Git refuses to overwrite the VPS copy because doing so could delete local work. This is a protection, not a GitHub or Mshauri application failure.

Important: the VPS should keep server-specific values in deploy/.env.production. It should not customize pnpm-workspace.yaml. That source file should normally match GitHub.

2. One-time repair for the error

1

Connect to the running VPS

ssh root@64.247.178.45
2

Enter the existing repository

cd /var/www/mshauri

If that path is different on your VPS, use the folder that contains deploy/3-update.sh.

3

Back up the local file change

git diff -- pnpm-workspace.yaml > /root/pnpm-workspace-local-change.diff
ls -lh /root/pnpm-workspace-local-change.diff
4

Check all local changes

git status --short

Continue only if the known conflicting source file is pnpm-workspace.yaml. If other important files are listed, stop and review them before restoring anything.

5

Restore the GitHub version of that file

git restore pnpm-workspace.yaml

This restores only the conflicting source file. It does not remove the production environment file or advert uploads.

6

Run the update script

bash deploy/3-update.sh

3. What the update script does

deploy/3-update.sh is the only command needed for normal application updates. It:

  1. Pulls the latest code from the GitHub main branch.
  2. Preserves the VPS environment configuration.
  3. Reconciles PostgreSQL access.
  4. Installs packages with the locked versions.
  5. Runs the TypeScript library checks.
  6. Builds the API and frontend.
  7. Applies database schema changes.
  8. Restarts the API through PM2.
Do not run these for a normal update: deploy/1-install-vps.sh, deploy/2-setup-app.sh, or git clone. Those are for first-time VPS setup.

4. Every time you commit new changes

On your development computer or Replit

Commit and push the changes to the GitHub main branch. Confirm the push completed before updating the VPS.

On the VPS

ssh root@64.247.178.45
cd /var/www/mshauri
bash deploy/3-update.sh

You do not need to run git pull separately because the update script performs the pull itself.

5. Verify every update

cd /var/www/mshauri
git log -1 --oneline
pm2 status
pm2 logs mshauri-api --lines 50
sudo nginx -t
curl -I https://mshauri.marichomedia.com

Expected results:

  • git log shows the latest GitHub commit.
  • PM2 shows mshauri-api online.
  • Nginx reports a successful configuration test.
  • The website responds over HTTPS.

6. If an update fails

Check the repository state

cd /var/www/mshauri
git status --short
git diff --stat
Do not use git reset --hard as a first fix. It can delete local tracked changes. Do not restore files until you know what they contain.

If only pnpm-workspace.yaml is listed

git diff -- pnpm-workspace.yaml > /root/pnpm-workspace-local-change.diff
git restore pnpm-workspace.yaml
bash deploy/3-update.sh

If other files are listed

Stop and save the details:

git status --short
git diff --stat
git diff -- deploy/.env.production

Do not commit production secrets or use a forced reset. The production environment file should remain local to the VPS. Advert uploads should remain outside the Git checkout.

If the API does not restart

pm2 status
pm2 logs mshauri-api --lines 100
pm2 restart mshauri-api --update-env

If the log reports missing environment values or database access errors, check deploy/.env.production and PostgreSQL configuration before retrying the update.
